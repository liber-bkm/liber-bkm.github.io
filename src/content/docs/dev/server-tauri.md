---
title: Server and Tauri split
description: Core, server, IPC, offline desktop, and CSP.
---

`liber-core` owns logic. `liber-server` (axum) exposes `/api/v2/*` JSON and serves the built frontend for self hosting (`liber serve`). `liber-tauri` calls core directly over Tauri IPC, no localhost hop. `/api/v2` is pinned two ways: per-resource handler tests assert exact bodies, unions, and error envelopes, and a checked-in `openapi.json` (generated by utoipa annotations, refreshed with `UPDATE_OPENAPI=1`) snapshots every route plus method, params, statuses, and the core schemas. Every new endpoint ships both: a `#[utoipa::path]` annotation with all reachable statuses, and handler tests covering the union branches and the error shapes. Typed request and response structs live in `api.rs`; free-form unions stay `serde_json::Value` with `body = Object` in the annotation and exact-key assertions in the tests.

Tauri specifics: `#[tauri::command]` functions must live in the binary crate as private fns (public commands in the lib trigger E0255 duplicate macro definitions). Frontend commands run before-build from `crates/` as cwd, hence `pnpm --dir ../frontend`. IPC mirrors REST JSON shapes so UI logic is shared: `frontend/src/tauri.ts` branches on `isTauri()` per function with a REST fallback, and commands return the same unions (delete confirm gates, add duplicate with existing). Opening records history over IPC and returns the URL; the frontend opens it with the opener plugin (needs `opener:allow-open-url` in the capability file, plus `opener:allow-default-urls` for the URL scope). File opens (archived copy, attachments) go through new `open_archive_external` and `open_attachment_external` commands that stage one stable temp file per item and call Rust-side `open_path`, which performs no scope check and needs no extra permissions. On Tauri the system back button walks a History API stack, gated to Tauri mode so web back-button UX is unchanged. IPC arg keys must match Rust param names exactly (serde, no case conversion).

Nix ships the desktop app as `packages.liber-desktop` (binary plus `.desktop` plus icons; the Tauri `.deb`/`.rpm` bundler never runs in the sandbox) and everything together as `packages.release-bundle`. `tauri dev` needs the Vite port pinned to the `devUrl` 1420 (`vite.config.ts` `strictPort`), though no shipped binary uses the dev server.

The webview CSP keeps scripts, styles, and images strict but allows `connect-src` over plain `http:`/`https:`: remote mode fetches a user-typed LAN URL, which no static allowlist can name, and the alternative is breaking remote-in-desktop entirely. Scripts stay `'self'`-only, so a compromised page still cannot run foreign code; only fetch targets widen, and only to URLs the user configured.

The workspace enables Tauri's `custom-protocol` feature, which turns off its `dev` cfg: without it every binary loads `devUrl` over real TCP and dies with a connection error unless a dev server runs. With it, all binaries serve the embedded frontend bundle in-process. Since the app uses `generate_context!`, assets re-embed only when the crate recompiles, so UI-only iterations need a Rust touch plus rebuild after `pnpm build`.

Archive viewing in Tauri renders fetched HTML via iframe `srcDoc` with the server-only "Open directly" link hidden; attachment and bookmark-file downloads go through blob object URLs instead of server download links, with a Save button for keep-where-you-choose copies. Sync exchange and snapshots run in Settings over IPC (plus `useRemote()` REST branches); direct push and pull stay CLI-only. App icons are generated from `Assets/liber-logo` with ImageMagick. The `rs.liber.app` identifier draws a Tauri warning about the `.app` suffix; harmless on Linux, revisit before macOS signing.
