---
title: Archiver internals
description: Builtin snapshot engine, backend chain, and external wrappers.
---

The builtin is monolith-class: `lol_html` parsing (never regex), stylesheet fetch with `@import` inlining and `url()` rewriting, srcset, fonts, media, and iframes embedded as sandboxed `srcdoc`. Scripts are stripped and `on*` handlers dropped, so archives are inert snapshots; text extraction feeds archive search. Caps: 20MB page, 10MB per asset, 50MB total, 45s, 6 workers.

Backends share one selection path: explicit `builtin`/`browser`/`single-file`/`monolith` is strict, `auto` chains browser (if one resolves), single-file binary, monolith binary, then builtin, warning at each fallback. The browser pipe dumps the live DOM via `--dump-dom` and runs it through the same embed pass; a failing browser falls back to static with a warning. External binaries are thin wrappers (`single-file [opts] url out`, `monolith url -o out`) tested with fake executables. The default path never shells out. Only Chromium-family browsers are auto-detected (an explicit Firefox `browser_path` fails the same way with a warning, since only Chromium dump flags are used). External runs report exit status plus stderr and reject outputs under 100 bytes, so empty snapshots surface as errors instead of blank archives.

Archive-at-creation is a caller-side post-step (CLI, API with additive `warnings`, Tauri), never inside `create_bookmark`, so import and sync paths stay unaffected. Netscape import carries its own `archive` flag instead (exposed on CLI plus API plus Tauri IPC plus the web settings form, failures as warnings). The API add and import shapes also take an explicit `archive_backend` (validated like settings), so callers can force `builtin` deterministically: `auto` resolution depends on which browsers and binaries the machine has, and tests must never depend on that. Nix provides the external binaries as runtime `PATH` only: the dev shell installs them and both packages wrap them in. They are never build inputs, since the npm based single-file-cli setup hook pollutes the Node env and breaks the offline pnpm build when placed there.

The reqwest blocking client must be built on a blocking thread: building it inside an async handler panics, so the server constructs it inside `spawn_blocking`. The same rule covers whole archive runs, not just client construction: add, update, post-archive, and import handlers run archive work in `spawn_blocking` with a fresh store while holding the write lock across the await. CI caught what local runs could not: the dev shell ships external archiver binaries, so `auto` backend resolution never reached the builtin reqwest path locally, while runners without those binaries panicked.
