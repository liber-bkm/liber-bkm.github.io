---
title: Android internals
description: Private storage, remote mode, deep links, and build notes.
---

`dirs` returns `None` on Android, so the Tauri app resolves its config in `.setup()`: system dirs present means desktop `load_config()`, otherwise `load_config_from` rooted at `app_data_dir` (config plus `library/` side by side). `cfg!(target_os = "android")` forces the builtin archiver and errors git snapshots; browser and external archiver binaries cannot exist there. Share receive is the `liber://add?url=` scheme via `tauri-plugin-deep-link` with an `AddDialog` prefill; the frontend uses `invoke("plugin:deep-link|get_current")` plus the `deep-link://new-url` core event directly, with no npm wrapper package (the wrapper once poisoned the offline pnpm store and broke the nix frontend build, so it stays out). System share-sheet SEND intents need a manifest entry plus intent handling and are not covered by the scheme.

Remote mode is client side only: `liber-remote-url` plus `liber-remote-token` in `localStorage`, base URL prefix plus derived bearer (`HMAC(token, "liber-bearer-v1")` hex, same as the server checks) in `api.ts`, and a third `useRemote()` branch in `tauri.ts`; the login form stays local-only. Device builds belong to the user via `.#android-fhs`; full commands in [Install on Android](/install/android/).

Mobile entry: the cdylib needs Tauri's `start_app` symbol, so `lib.rs` includes `main.rs` as `mod app` under `cfg(mobile)` only and exposes it through `#[tauri::mobile_entry_point]`. That required `extern crate self as liber_tauri` and `pub(crate) fn main`; desktop builds never compile that path, so behavior there is unchanged. `compileSdk`/`targetSdk` are pinned to 36 in the generated `app/build.gradle.kts`: the stable channel has no android-37 platform and every Tauri library module already targets 36; re-running init may reset the pin. Gradle's `node tauri` step resolves `./tauri` as a file in `crates/liber-tauri`, so the repo ships that symlink into the CLI JS. Distrobox-on-NixOS builds must scrub leaked Nix paths from `PATH` and use an isolated `CARGO_TARGET_DIR`, or store RUNPATHs poison the binaries. Gradle daemons outlive FHS env rebuilds and keep the old environment: after any flake or SDK change, `./gradlew --stop` before rebuilding, or `node`/`cargo` resolve to garbage-collected store paths and every `rustBuild*` task fails with a bare exit code.
